Query Remote Database — JOIN & Subquery

Mempelajari cara menggabungkan data dari beberapa tabel menggunakan INNER JOIN dan LEFT JOIN, menyusun subquery untuk kebutuhan analisis bertingkat, serta membuat view sebagai query tersimpan pada PostgreSQL di Neon.Tech.

📚 Kelompok: Remote Database — Neon.Tech
🎯 Sub-CPMK: CPMK2
🧭 Indikator: IK 1.3, IK 3.1
⏱️ Durasi: 100 menit
1 Tujuan Pembelajaran
  • Mahasiswa mampu menjelaskan konsep penggabungan data antar tabel menggunakan JOIN.
  • Mahasiswa mampu membedakan dan menerapkan INNER JOIN serta LEFT JOIN sesuai kebutuhan data.
  • Mahasiswa mampu menyusun subquery untuk mengambil data berdasarkan hasil query lain.
  • Mahasiswa mampu membuat VIEW sebagai query tersimpan untuk mendukung analisis data dan pengambilan keputusan administratif.
2 Konsep Dasar JOIN & Subquery

Pada basis data relasional, data administrasi sering tersebar di beberapa tabel yang saling berhubungan (misalnya tabel pegawai dan tabel divisi). Untuk menampilkan data gabungan dari beberapa tabel tersebut, digunakan perintah JOIN. Selain itu, subquery (query di dalam query) digunakan untuk mengambil data secara bertahap, dan view digunakan untuk menyimpan query yang sering dipakai agar dapat dipanggil kembali seperti tabel biasa.

🔗 INNER JOIN

Menampilkan hanya baris data yang memiliki pasangan cocok di kedua tabel.

↩️ LEFT JOIN

Menampilkan seluruh baris dari tabel kiri, meskipun tidak ada pasangan cocok di tabel kanan.

🧩 Subquery

Query yang diletakkan di dalam query lain, digunakan sebagai filter atau sumber data sementara.

🗂️ View

Query tersimpan yang berperilaku seperti tabel virtual, memudahkan analisis data berulang.

3 Praktik: INNER JOIN & LEFT JOIN
1

Siapkan tabel pendukung

Buat tabel divisi pada SQL Editor Neon.Tech, lalu hubungkan dengan tabel pegawai yang telah dibuat pada Pertemuan 7:

CREATE TABLE divisi ( id SERIAL PRIMARY KEY, nama_divisi VARCHAR(50) ); ALTER TABLE pegawai ADD COLUMN divisi_id INT REFERENCES divisi(id);
2

Isi data divisi & perbarui data pegawai

Tambahkan data divisi, lalu kaitkan setiap pegawai dengan divisinya menggunakan UPDATE.

INSERT INTO divisi (nama_divisi) VALUES ('Kesekretariatan'), ('Keuangan'), ('Umum'); UPDATE pegawai SET divisi_id = 1 WHERE nama = 'Budi Santoso';
3

Gabungkan data — INNER JOIN

Tampilkan nama pegawai beserta nama divisinya, hanya untuk pegawai yang sudah memiliki divisi:

SELECT pegawai.nama, pegawai.jabatan, divisi.nama_divisi FROM pegawai INNER JOIN divisi ON pegawai.divisi_id = divisi.id;
4

Tampilkan seluruh pegawai — LEFT JOIN

Tampilkan seluruh pegawai meskipun belum memiliki divisi (nilai divisi akan kosong/NULL):

SELECT pegawai.nama, pegawai.jabatan, divisi.nama_divisi FROM pegawai LEFT JOIN divisi ON pegawai.divisi_id = divisi.id;
💡 Gunakan INNER JOIN saat hanya ingin menampilkan data yang lengkap/berpasangan, dan LEFT JOIN saat ingin tetap menampilkan seluruh data dari tabel utama walau sebagian relasinya belum terisi.
4 Praktik: Subquery & View
1

Menyusun subquery

Tampilkan pegawai dengan gaji di atas rata-rata seluruh pegawai menggunakan subquery pada klausa WHERE:

SELECT nama, gaji FROM pegawai WHERE gaji > (SELECT AVG(gaji) FROM pegawai);
2

Subquery pada klausa FROM

Hitung jumlah pegawai per divisi menggunakan subquery sebagai tabel sementara:

SELECT nama_divisi, jumlah_pegawai FROM ( SELECT divisi.nama_divisi, COUNT(pegawai.id) AS jumlah_pegawai FROM divisi LEFT JOIN pegawai ON pegawai.divisi_id = divisi.id GROUP BY divisi.nama_divisi ) AS rekap_divisi;
3

Membuat VIEW

Simpan query gabungan pegawai & divisi sebagai view agar dapat dipanggil kembali tanpa menulis ulang query:

CREATE VIEW data_pegawai_lengkap AS SELECT pegawai.nama, pegawai.jabatan, divisi.nama_divisi, pegawai.gaji FROM pegawai LEFT JOIN divisi ON pegawai.divisi_id = divisi.id;
4

Menggunakan VIEW

Panggil view seperti memanggil tabel biasa untuk kebutuhan analisis data:

SELECT * FROM data_pegawai_lengkap ORDER BY gaji DESC;
⚠️ View tidak menyimpan data secara fisik — setiap kali dipanggil, PostgreSQL akan menjalankan ulang query yang tersimpan di dalamnya berdasarkan data tabel terkini.
5 Latihan / Tugas Praktik

📝 Tugas Individu

  1. Buat tabel pengirim (id, nama_instansi) dan hubungkan dengan tabel surat_masuk dari Pertemuan 7 melalui kolom pengirim_id.
  2. Tampilkan data surat beserta nama instansi pengirimnya menggunakan INNER JOIN.
  3. Tampilkan seluruh surat meskipun instansi pengirimnya belum terdaftar, menggunakan LEFT JOIN.
  4. Buat satu subquery untuk menampilkan instansi dengan jumlah surat masuk terbanyak.
  5. Buat sebuah VIEW bernama rekap_surat_masuk yang menggabungkan data surat dan instansi pengirim, lalu ambil tangkapan layar hasilnya.
